## 0. 改造原则（先立规矩，避免把做对的东西改坏）

| 原则 | 具体含义 |
|---|---|
| **尊重原有设计** | 不动分层结构、不动 fail-closed、不动"风险只能抬高不能降低"、不动三套引擎并存、不动 31 个既有路由的契约 |
| **渐进式** | 每个增量独立可验证、可回退（新增功能一律带开关，默认关闭时行为与现在**完全一致**） |
| **价值优先** | 先补"闭环"（业务价值最高），再补"能力深度" |
| **保持兼容** | 既有接口/脚本的请求与响应字段不变；新增字段一律可选；`mock` 后端仍是 clone 即可跑的默认 |
| **不过度设计** | 见第 3 节"明确不做"——这一节和路线图同等重要 |
| **新功能不进 `main.py`** | `main.py` 已 3111 行，新能力一律新建模块，`main.py` 只做接线（渐进式解耦，**不整体重写**） |

## 1. 增量清单与优先级

### I-0 · 自检语义修正（0.5 人日 · 零风险 · 应最先做）

- **解决**：D2、0.2-5（"九层全通"含水分）
- **做法**：`scripts/smoke_test.py` 增加 `--strict`（服务未启动 = 失败）；
  默认模式下汇总把"跳过"单列为 **"未验证 N 层"**，退出码区分"全通 / 有未验证"；
  README 与 `docs/overview.md` 的表述与实测口径对齐。
- **验收**：服务未启动时 `--strict` 退出码非 0；默认模式汇总明确显示"9 层中 1 层未验证"。

### I-1 · 测试与 CI 门禁（5–8 人日 · 低风险）★可信度地基

- **解决**：D1、D3、D4（阻断级）
- **做法**：
  1. `tests/` + pytest 骨架，先覆盖 **6 个核心模块**（都是"坏了会静默出错"的地方）：
     `sandbox/policy`（白名单正反例/路径/指纹）、`sandbox/approvals`（状态机全迁移+过期+重放）、
     `parse_intent`/`validate_intent`（含防注入）、`observability/costs`（成本口径/缓存折扣/双维对账）、
     `rag/store`（RRF/BM25/向量兜底）、`observability/tracer`（父子归并 + 唯一事实源）
  2. `ruff`（lint + format）；`mypy` **只覆盖新增模块**（不一次性修 1.3 万行）
  3. `.github/workflows/ci.yml`：pytest → ruff → `smoke_test.py` → `security_check.py` → `mcp_check.py` → 离线评测（**全部零成本**）
  4. 评测基线：把 `eval/reports` 的历史报告转为基线，新增 diff 报告（先"记录并对比"，不阻塞合并）
- **验收**：`pytest -q` 全绿且覆盖上述模块；CI 在 push/PR 上跑通；评测有基线 diff；**故意破坏一处白名单规则，CI 必须变红**（证明门禁真的有效）

### I-2 · 事件（Incident）+ 出站通知（3–5 人日 · 低风险）★业务价值最高

- **解决**：E1、E2、D12、E6（部分）
- **做法**：
  - 新增 `app/incident/`：事件模型（`id/status/severity/host/service/source/owner/timeline/linked_alerts`）、
    存储（先沿用项目风格的 JSONL + 索引，**不引入数据库依赖**，保留后续换 SQLite 的口子）、
    状态机 `open → ack → resolved`（支持 `reopened`）
  - 新增 `app/notify/`：适配器接口 + **通用 webhook** + 钉钉/飞书（含签名）+ 重试与失败记录 + 脱敏钩子
  - 接线：`/webhook/alert` 诊断完成 → 建立/并入事件 → 推通知；
    审批单创建 → 推通知；处置执行完成 → 更新事件并通知
  - 新增接口：`GET /incidents`、`GET /incidents/{id}`、`POST /incidents/{id}/ack`、`POST /incidents/{id}/resolve`
- **验收**：本地起一个 mock 通知接收端，模拟告警后**确实收到**诊断结论；待审批单产生时**确实收到**提醒；
  事件时间线完整可查；通知失败有重试记录且**不阻塞**主流程；**未配置通知时行为与现在完全一致**

### I-3 · 告警聚合与去重工程化（3–4 人日 · 中风险）

- **解决**：E3、E4、E2（关联部分）
- **做法**：
  - 去重升级：精确键 → **指纹聚类**（alertname + host + service + 关键 labels）+ 时间窗 → 多告警并入 1 个事件
  - 内存态改造：滑动窗口 TTL + 定期清理（消掉 `_ALERT_LAST_SEEN` **无界增长**）
  - webhook 异步化：`ALERT_ASYNC=1` 走后台任务，避免 Alertmanager 超时；入站幂等键防重放
  - 维护窗口与抑制规则（配置化、简单实现，不做规则引擎）
- **验收**：一次推 50 条同源告警 → **聚成 1 个事件、只跑 1 次诊断**（用 mock 计数证明）；
  连续推 10 分钟内存不增长；异步模式下 webhook 响应 < 200ms；`ALERT_AGGREGATE=0` 可回退到现有精确去重

### I-4 · 安全执行面收口（3–5 人日 · 中风险）★修真实缺陷

- **解决**：C1、C2、C3、C4、C5、C6、C8、C11
- **做法**：
  1. 命令解析为**固定绝对路径** + 最小化 `PATH`/环境 → 消 PATH 劫持（C1）
  2. 审批存储加 `flock` + 原子写 + `fsync`，`consume` 用 CAS 语义 → 消跨进程双执行（C2）
  3. `execute` 前校验 `expires_at` → 消"无时限"（C3）
  4. `consume` 后**回写真实结果**（**保持"先消费再执行"的顺序不变**）→ 消 `result_ok` 错报（C4）
  5. 超时同时 kill **进程组与容器**（`--cidfile` + `docker rm -f`）→ 消资源泄漏（C6）
  6. 读路径按注释收紧到 `.log`（或明确放开并改正注释——二选一，写进文档）（C5）
  7. 审计补齐：policy DENY、开票、失败尝试、只读 `run_command`（C8）；只读命令统一收口（C11）
- **验收**：对抗性用例全部被拦**且留痕**——PATH 劫持、过期单执行、跨进程双执行（两个进程抢同一张单）、重复执行、越权读；
  `approvals.jsonl` 的 `result_ok` 与实际执行结果一致；**每条新增拒绝规则都配一条正例**（防止把能用的命令也拦掉）

### I-5 · 自监控与状态外置（4–6 人日 · 中风险）

- **解决**：D5、D6、D7、D8、D9、A6、A7
- **做法**：`prometheus_client` + `/metrics`（请求数/延迟直方图/模型 token 与成本/拒绝计数/事件数/通知失败数）；
  `/healthz` 深度探依赖（模型连通性缓存探针、索引可加载、磁盘可写，`/health` 保持兼容）；
  结构化日志（JSON + 请求 ID）+ `write_audit` 加锁；日志轮转与保留策略；`/audit` 分页（不再全量读）
- **验收**：`curl /metrics` 返回 Prometheus 文本；`/healthz` 能报出依赖故障；audit 查询耗时与文件大小解耦；
  `traces.jsonl` 自动轮转且不再依赖人工 `.bak`

## 3. 明确不做（防过度设计）

| 不做 | 为什么 |
|---|---|
| 不引入向量库（Milvus / Chroma / pgvector） | 91 块语料一次矩阵乘法几毫秒；换来的只有运维成本 |
| 不做 RAG rerank | 同规模下收益低于复杂度；等语料上千块再说 |
| 不上 K8s / 消息队列 / 微服务 | 单机 compose + 后台任务足够；这个规模上分布式只会增加故障面 |
| 不引入 RBAC / 多租户 | 先补"单令牌可自批自执"这个**真实**漏洞（I-4），而不是先堆一套权限系统 |
| 不重写 `main.py` | 只做"新功能不进 main.py"的渐进式解耦；整体重写会把已验证的行为一起丢掉 |
| 不动三套引擎并存 | 那是本项目的对比资产，删掉等于销毁证据 |

### 7.2 与方案的三处偏差（都是有意调整，不是缩水）

| 项 | 方案原定 | 实际做法 | 原因 |
|---|---|---|---|
| CI 必需档是否跑 `smoke_test.py --strict` | 跑 | **不跑**；接口层改由 `tests/test_api_smoke.py` 在进程内验证 | smoke_test 的快速档本身包含真实模型调用（第 2 层、RAG 问答、`POST /chat`、`/rag/ask`、`/webhook/alert`），**无密钥环境必然失败**。零成本档需要的是一套不需要密钥的接口验证 —— TestClient 正好满足，而且比"起服务再探活"更稳。`--strict` 仍保留给本地与可选档使用 |
| lint 覆盖范围 | 全仓 | **只强制 `tests/`** | `app/` + `scripts/` 当时有 **69** 处历史 lint 债（一次性大扫除会把真实改动淹没在 diff 里），已显式登记、按里程碑纳入。★ 这里原本写的是 55 —— 那是我当时**没有实测就写下的数字**，M3 核账时才发现。**误差只出现在文档里，不影响代码**，但正是本项目反复强调的那类问题：数字必须来自实测（现为 59，见 §8）。 |
| mypy 覆盖范围 | `tests/` | `tests/` + `follow_imports = "silent"` | 不设 silent 时，仅 `import app.main` 就会带出近百条老代码的历史类型错误 —— 那只会让人学会无视 mypy |

### 7.3 本里程碑发现并处理的缺陷

- **已修**：审批单时间戳只写盘不回填（同进程内 `created_at`/`approved_at` 全为 `null`，重启后自愈）；
  `/metrics/summary` 在 trace 文件位于项目外时 500；
  模型返回裸 `null` 时意图校验抛 `TypeError` → HTTP 500 且不写审计。
- **已登记待办**：D2–D7、成本归集的两条（成环吞钱、兜底价低估）、55 处 lint 债。
  详见 [`01-audit.md`](01-audit.md) §6.2 与 §6.3 —— **登记在案才不许它悄悄消失**。

### 7.4 一条必须记住的教训

新测试一度把假 trace 写进真实 `logs/traces.jsonl`，结果是**对外成本指标从 ¥0.9253 掉到 ¥0.0774**（被压低 12 倍）。
已用非破坏性方式清理（标记 `source=selftest`，行数不变 1374）。
→ **测试污染不是"日志多几行"，而是让可观测性数字变成假的。** conftest 的隔离装置是必需品，不是讲究。

## 8. M3 实施结果（**已完成并验收**）

范围：**I-4 安全执行面收口** —— C1–C8、C11 与 M2-1 共 10 条真实缺陷。
详细逐条见 [`01-audit.md`](01-audit.md) §8；方案见 [`05-design-m3.md`](05-design-m3.md)。

| 项 | 结果 |
|---|---|
| 用例 | **594 条全绿**（M2 为 509，M3 新增 85） |
| 其它门禁 | ruff / mypy(16 文件) / security_check 23 项 / mcp_check 9/9 / 检索基线 —— 全通 |
| lint 债 | 66 → **59**（新增代码零新增债） |
| 跨进程双执行 | **两个真进程**抢同一张单 → 恰好一个成功，日志里只有一条 `consumed` |
| 假 PATH | 假 `df` 放进 PATH：Linux 跑真程序、Windows 直接拒绝 —— **两种情况假程序都没被执行** |
| 超时回收 | 真起"子进程 + 孙进程 sleep 600"，超时后两个 pid 都已消失 |
| 门禁自证 | 执行器注回 11 种旧行为 → 11/11 被判红；策略注回历史缺陷 → 精准变红 |
| **真机验证** | `tail_log --service wp-app` 在真实 ssh 后端取到 15 行容器日志 —— 并因此抓到一条**打桩测试完全没覆盖的真机回退**（见 §8.3 的 M3-3） |

**选定的两处设计口径**（均已写入代码与文档）：
读路径按**方案 A**（`.log` + 显式放行 syslog/messages/kern.log/auth.log，secure/wtmp/btmp/audit 不给，且读写都生效）；
过期审批单按**方案 A**（拒绝执行并标记 `expired`，需要时重新开票）。

**一条跨里程碑的教训**：M3-3 那条回退说明 ——
**打桩测试全绿不等于功能没坏**。收口了执行路径之后，必须拿真机跑一次真正的读取，
否则"改对了安全性、弄坏了能力"会一直没人知道。
